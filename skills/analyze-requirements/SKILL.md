# 需求澄清

1. 读取需求来源、目标项目的 `AGENTS.md` 和已有需求文档。记录可定位的工单、PRD 或对话结论。已有需求时复用其目录和编号。
2. 提取目标、范围和边界，按角色、触发条件、主流程和异常整理用例。必要时核实产品现状或代码中的现有行为，将现状证据和这次要实现的行为分别写清。
3. 将验收条件写成可观察的结果，按 `AC-01`、`AC-02` 编号。优先覆盖成功路径、明确约束以及会改变结果的重要边界。更新时保留仍有效的编号。
4. 先从现有材料和代码消除歧义。对仍会改变业务结果、权限、接口或数据语义的问题，说明影响并给出清晰选项。能接受的低风险假设记入文档并继续。若确实缺业务决定，先产出已明确的部分，标明哪些验收条件待澄清。
5. 用 [requirements.md 模板](assets/requirements.md) 新建或更新需求文档。优先采用项目要求的路径和格式，默认写入项目根目录下的 `docs/changes/<work-item>/requirements.md`。有工单号时使用 `<工单号>-<短标题>`，否则使用简短语义名。沿用已有目录，避免为同一个需求重复建档。

按用户授权的阶段推进。只做需求分析时，以文档路径、关键验收条件和待决问题收尾。
