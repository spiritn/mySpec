# 代码实现

1. 读取适用的项目指令、用户要求以及工作项已有的 `requirements.md` 和 `design.md`。按 `AGENTS.md` 指定的路径读取通用编码规范，读取前检查可读性。项目未指定路径时，依次寻找项目根目录的 `.agents/standards/coding.md` 和 `~/.agents/standards/coding.md`。以项目约定为准。
2. 查看工作区现有改动、实际入口、相似实现和相关测试。守住当前任务范围，保留已有改动和调用方依赖的行为。明确的小修可直接实现。直接实施独立新需求且尚无需求文档时，按项目约定建档，默认用 `docs/changes/<work-item>/requirements.md` 简记范围和验收条件。
3. 按依赖顺序完成可验证的改动。优先复用现有模块、数据类型和测试基础设施。发现设计与代码现状不符时，先查证，记录需要调整的实现及理由。若偏差会改变已约定的业务行为、权限或公开契约，先澄清受影响的部分。
4. 检查最终 diff，逐项对照验收条件，运行项目提供的针对性测试、类型检查或构建。优先覆盖典型路径及本次变更引入的关键边界。对失败项区分当前改动的问题和有证据支持的环境或基线问题。
5. 报告实际变更、验证命令和结果，以及剩余未验证项。工作项已有 `design.md` 时回填实施记录。根据用户授权执行提交、推送或部署。
