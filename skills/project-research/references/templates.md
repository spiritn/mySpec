# 项目调研模板

调研是主文档中的介绍章节，先让人看懂别人怎么做。按项目选择“竞品调研”“市场分析”或“方案调研”，不默认同时创建三节。以下是可复用的介绍顺序，按问题取舍内容，不为填满字段补造事实。

## 竞品调研

在 `整体思路.md` 中按厂家或产品介绍。优先用短段；只有确实便于比较的短字段才用表格，不把长技术说明挤进宽表。

```markdown
## 竞品调研

一两句话说明主要厂家分别采用哪类做法，以及为什么选它们作参照。

### 厂家 · 产品名称

**推出时间与定位：** 何时推出，服务谁、解决什么问题。首发时间查不清时，写“目前最早查到的公开介绍为某日期，首发未确认”。

**怎么做：** 用普通话讲清关键步骤和核心亮点。只展开与我们项目有关、汇报时会被追问的技术，例如用什么模型识别什么、怎样分割或跟踪、结果怎样进入编码器。

**公开成果：** 厂商或独立测试公布了什么结果，和谁比、在哪类场景和条件下成立。附直接支持这项事实的来源。

**尚未公开：** 所查资料没有说明、但会影响理解或复用的核心细节；无关缺项不罗列。

其他重要产品沿用以上顺序，不必每家都写满四段。

**对本项目的启发：** 用短句说明值得借鉴哪一步、还需自行验证什么；与厂商公开事实分开。
```

日期区分产品首发、功能升级、资料发布与本次查阅。没有结果就说尚未查到公开测试，不能用发布消息充当商业成果。厂商节省比例保留其比较对象、场景及关键条件；条件不同不据数字直接排名。

技术说明区分已公开和推测：视觉模型与多模态模型、检测框与像素掩码、编码标准与实现库／芯片分别写清。支持某标准不证明使用某编码器；专利展示的办法不自动等于商用品当前实现。必要时写“所查资料未披露”，不补猜模型结构、参数量、块粒度或设备内部方案。

## 市场分析或方案调研

沿用“对象／办法 → 怎么解决问题 → 已有结果 → 与我们有关的限制”的介绍顺序，内容随项目变化。

- **市场分析：** 谁有何需求，现有产品或服务怎样满足，用户为什么购买或仍不满意。确需市场规模、增长或价格时，写清来源、统计口径和日期；不能由少数厂商宣传推成整个市场结论。
- **方案调研：** 各种可行办法怎样工作、适合什么条件、主要成本及已有结果；保留现状或简单办法作参照。直接解释差别，不只列“支持／不支持”或风险清单。

只比较与目标有关的对象。术语沿用主文档定义，必要的新词先用普通话解释。来源放在相关事实附近，阅读正文即可理解核心内容，无需先点开全部资料。

## 按需展开的资料

主文档留下可汇报的介绍；确需保存技术细节、原文和数据条件时，优先更新 `调研/` 中同主题材料。不要为每次审查新建报告或索引。

专项资料先用不超过100字说明主题与主要发现，再按读者问题组织内容：产品与时间、工作过程、测试结果、尚未公开及相关原文。详细取证可用“事实／来源／适用条件”短表，不能取代主文档的清楚介绍。

来源应能追溯到具体页面、章节、代码或实验记录。在线资料注明实际查阅日期；本地资料注明可核实的版本、提交号或文件日期。结论回写整体思路，未解决问题关联其待定与验证、涉及选择时更新同一份决策表，不再维护另一套进度和决定。
