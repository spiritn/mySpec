# 代码实现

1. 读取适用的项目指令、用户要求和同一工作项的 `tasks.md`、`design.md`、`requirements.md`（如有）。按 `AGENTS.md` 指定的路径读取通用编码规范，读取前检查可读性。项目未指定路径时，依次寻找项目根目录的 `.agents/standards/coding.md` 和 `~/.agents/standards/coding.md`。以项目约定为准。
2. 查看当前分支和工作区的实际改动、入口、相似实现和相关测试，保留用户已有改动。续跑时对照 `tasks.md` 的执行记录与实际代码，保留有效的已有实现。已有改动尚待验证时，先验证，再决定要补哪些工作。明确的小修可以直接实现。直接实施独立新需求且尚无需求文档时，按项目约定建档，默认用 `docs/changes/<work-item>/requirements.md` 简记范围和验收条件。
3. 按依赖顺序选择并完成可执行的任务，复用现有模块和测试基础设施。开始依赖任务前确认它需要的接口、类型、配置或迁移产出在当前代码中可用。依赖缺失时先补齐授权范围内的前置任务，或记录阻塞并继续处理独立任务。发现方案与代码现状不符时先查证并记录实际取舍。若偏差会改变已约定的业务行为、权限或公开契约，先澄清受影响的部分。
4. 交付或创建 PR 前由当前实现者自查实际 diff。逐项核对验收条件、变更范围、调用方影响和关键边界。修复本次范围内证据明确的问题，再运行针对性测试、类型检查或构建，记录实际结果和未验证项。PR 阶段使用独立的 `$review` 核实变更。
5. 将实际改动、验证结果和剩余事项回填 `tasks.md` 对应条目，满足该项完成条件后勾选。暂时无法验证时，保留未完成状态并写明原因。只有设计文档时，可把已执行检查和方案偏差记到其中。按用户授权执行提交、推送或部署。
