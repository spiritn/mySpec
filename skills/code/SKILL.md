# 代码实现

在用户已授权范围内完成真实行为，保留已有成果，以实际代码和验证说明完成程度。主会话负责调度、任务记录、集成和整体验收；`code_implementer` 执行明确分配的任务，不同时接管这些职责。

## 先核对任务与现场

1. 读取用户要求、适用项目指令和同一工作项的任务、方案、需求及相关验收。按项目指定路径读取通用编码规范；未指定时先检查项目 `.agents/standards/coding.md`，再检查 `~/.agents/standards/coding.md`。以适用项目约定为准。
2. 核对当前分支/工作区、基线与实际改动、任务记录和已有验证。保留用户及其他执行者的改动；已有实现尚待验证时先验证，不重复写。已获实施授权的明确小修可以直接实现；独立新需求无文档时由主会话在已有约定位置简记范围和验收，默认沿用 `docs/changes/<work-item>/`，不强制补齐无关阶段文档。
3. 确认被分配的目标、允许写入的模块/文件及测试范围、相关约定、前置产出和完成条件。来自 workflow 时，主会话先核对用户对当前方案的确认或明确实施授权；不能仅凭已有方案、任务清单或技术评审通过开始编码。执行者按主会话明确交接的授权范围工作，不重复要求用户确认。需要的接口、类型、配置或迁移必须在执行工作区实际可用。边界不清时先只读定位，由主会话明确归属，不让多个执行者自行扩展到相同文件。

## 实现与协作

- 优先复用已有模块、相似实现和测试设施，采用满足需求的简单改动。只做本次任务需要的工作；相关边界、历史数据和失败处理按真实需求及方案执行，不凭空扩展为全库重构。
- 在分配范围内检查同类入口与配套文案、配置、文档和测试；改完按旧名称、旧数值及已失效的能力说明搜索遗漏，区分有关命中与无关同名内容。涉及他人归属或范围外配套变更时，交主会话统一处理，不自行扩权。
- 执行者不是代码库中唯一的工作者。只写分配范围，不回退他人改动，不用 reset、整文件覆盖或恢复基线来清理不属于自己的差异。开始和交回前重新读取受影响文件及 diff，适应已发生的相关变化。
- 前置缺失时，主会话可以在原授权内补齐或调整顺序；被委派者返回缺口与影响，不能擅自接管他人的任务。继续能够独立完成的部分，不把一项阻塞扩大成全部停工。
- 发现方案与实际代码不符，先查证。范围内可逆的实现细节可合理处理并记录；改变业务行为、权限、公开契约或越出写入归属时，交主会话协调必要决定，不自行替用户确认。
- 只有依赖实际具备、写入范围不会冲突、共享契约清楚时才安排并行。分支或独立工作区的结果要交回具体位置与状态，由主会话核对并集成；尚未进入目标工作区的产出不能记作已集成。

## 自查与针对性验证

1. 查看本任务实际 diff，逐项核对验收、改动范围、调用方和相关边界，修复有证据且在本次范围内的问题。不能仅凭代码存在、返回200或构建成功就认定业务目标完成。
2. 使用项目现有检查方式。先明确或必要时复现基线问题，按改动选择相关测试、类型检查或构建；覆盖可观察行为和有实际风险的边界，缺少能捕获回归的用例时补充。不为低影响机械改动堆镜像测试，不削弱断言或删除失败测试来制造通过。
3. 如实记录实际命令、环境与结果，区分本次引入的问题、已有失败及环境限制。没运行的检查不写通过，模拟测试不冒充真实数据库或外部链路验证。检查失败时说明原因、影响和解除条件，继续独立可做工作。
4. 已通过的检查只在相关改动、失败或未解决疑点需要时重跑；单个执行者不重复其他人的整套测试。主会话仍需针对集成后的代码执行必要共享检查，不能用各自测试通过替代组合验证。
5. 用户纠正或评审确认的真实行为错误，修复时复查受影响的同类，优先以回归测试、类型或结构约束防止复发；不能可靠自动判断时，在现有记录中简记理由。已有检查能覆盖时复用，不为小而可逆的改动补只匹配实现的测试。

## 角色调度与交接

小任务可以主会话直接完成。需要分担明确工作时，主会话用独立上下文调用 `code_implementer`，交接任务编号与目的、原始需求/方案入口和验收、执行基线与工作区、写入归属、前置产出、验证及限制。告诉执行者它不是独自在代码库工作，不能撤销他人修改。

子 Agent 只执行分配任务，不递归委派、不直接向用户重复提问、不统一改任务清单；必要问题返回主会话。优先使用可用原生角色；入口不可用时显式传入 TOML 中完整 `developer_instructions`，说明兼容加载，不把同名子任务当原生角色成功。

交回内容用普通中文说明：任务编号与实际状态、行为变化及文件、已完成验证与结果、未验证项/阻塞、对其他任务的影响，以及实现所在工作区或分支。正式 `tasks.md` 由主会话根据代码与证据统一回填。主会话自行实施时同样据实记录；无任务文件时可写入现有方案，不为记录工具输出新增文件。

## 集成、完成与评审

- 主会话核对各执行结果与任务基线，确保预期改动已进入目标工作区、他人改动保留、共享接口与数据一致；不只收集“完成”报告。
- 对照原始需求及全部相关验收，按用户实际使用入口验证组合后的业务路径与必要共享检查；前端核对相关设备、主题、地址与标题，接口核对响应，后台任务核对处理结果，按本次影响选择。单项任务通过不等于完整需求完成，发现跨任务缺口时补齐原范围内工作或记录具体阻塞。发布属于已授权目标时核对实际发布版本和线上结果，缺权限或环境时保留未验证，不能用本地通过代替线上验证。
- 采用未开始、进行中、已实现待验证、已完成、阻塞等实际状态。只有满足本任务完成条件才勾选；环境导致无法必要验证时保留未完成及原因，既有有效完成证据不随意清零。
- 实现者自查与独立代码评审分开。需要独立评审时由主会话按用户范围调用 review Skill，执行者不自行调度。需求、方案或代码变更后，复查受影响部分，不拿旧评审当新版本已通过。
- 用户只要求指定任务或编码阶段时按范围结束；已授权完整 workflow 时，由主会话继续到所指定终点。提交、推送、部署及数据操作按当前明确授权处理，不能因任务清单中出现就视为获准执行。
