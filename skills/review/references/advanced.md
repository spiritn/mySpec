# 进阶评审

## 选择性上下文

- 将输入组织为变更目的和验收条件、评审版本及 diff、带来源的关联代码与规则、专项问题和所需输出。以工单、文件、符号或契约定位信息，优先找直接相关的材料。
- 以改动的入口、符号、类型、配置键和事件名为检索种子。先读完整的变更单元、直接调用方和关键断言，再按影响扩展。关联仓库优先核对锁文件、版本声明或发布契约所指的版本。以服务接口、共享类型或消息格式验证跨仓库判断。
- 大型变更按行为或模块分批，维护覆盖记录。最后合看调用方、公共契约、跨批状态变化和部署顺序。结果中注明因权限、资料缺失或范围限制而未审到的部分。
- 已有语义索引时，将它与符号搜索和引用导航结合。索引块可按函数、类等语法边界，保留装饰器或注解、必要的导入和类型上下文。元数据保留仓库、提交、路径和行号。代码更新后同步索引并校验版本。索引过期、缺命中或重要依赖未入库时直接查被评审版本的源码。检索命中用于找线索，结论以实际代码和契约举证。

## 专项评审与合并发现

三专项的角色、独立上下文、等级和汇总规则以 [review Skill](../SKILL.md) 为准；各角度的检查提示和误报反例见[专项与举证细则](angles.md)。主会话统一版本与材料，各专项先独立判断，随后查证具体冲突并按根因合并。不得以投票或发现数量判断质量。

大型变更可按模块进一步划分，但保持需求完整性与逻辑正确性为首要目标。专项没完成、上下文不独立或来源缺失时如实说明；不用同一会话换三个标题冒充独立评审。

## 规则反馈

- 对用户纠正或评审确认的错误，优先建议在同一修复中加入能捕获真实问题的类型、静态检查或回归测试；能用接口或结构减少误用时优先考虑。只有不能可靠自动判断时才补简短文字规则，并说明限制。只读评审只提出建议，不自行修改规则、实现或检查。
- 加检查时区分存量欠账和本次新增违规，不能放宽规则让新问题通过。已有检查已覆盖的约束只引用检查入口，不重复堆文字规则；机器检查通过也不代替需求与真实使用验证。
- 从已确认的发现提炼可复用约束，优先考虑重复出现或后果高、适用范围明确的问题。保留已验证的典型触发条件，并由团队确认约束与处理等级。
- 优先更新项目已有的评审规范。同类文件缺失时，可在 `AGENTS.md` 记录项目规则的路径和加载条件。每条写清适用模块或路径、规则正文、来源、怎样验证、违反时如何处理，以及已批准的例外。更新时复核旧规则是否已失效。
- 规则增改需要得到授权。一般评审可提供可审阅的规则提案，包括依据、预期检出的风险和一个易误报的反例。

## 评估效果

- 选取一批已经复盘的历史 PR，固定基线、目标版本和可用规则。覆盖真实缺陷、改动正常的样本及高风险边界，记录人工确认的缺陷和正确行为。保留一批样本供规则或检索方案改动后的独立验证。
- 将发现按 PR 与根因去重，并由人核对真伪、证据和等级。精确率为正确发现数除以已判定的正式发现数，召回率为被检出的已知缺陷数除以已知缺陷总数。分母为零时记为不适用，未裁定项另计。报告覆盖范围和样本量。
- 比较方案时固定 PR、版本和评审目标，记录模型、检索方式和规则版本。除总体指标外，核对必须处理问题的漏报、证据缺失和评论噪声。发现基准未记录的真实缺陷时，由人确认并统一更新基准，再复核所有参与比较的方案。
