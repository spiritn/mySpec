# 代码评审

1. 确定被评审的范围和基线。优先采用指定 PR、分支、提交或文件，未指定时按现有上下文选择并说明。若评审当前工作区，检查暂存区、未暂存区和相关未跟踪文件。
2. 读取适用的项目指令，以及工作项的需求验收条件、设计、任务范围和实际验证记录。评审部分任务时，以指定任务及受其影响的现有行为为范围。按 `AGENTS.md` 指定路径读取可读的通用编码规范。项目未指定时，依次寻找项目根目录的 `.agents/standards/coding.md` 和 `~/.agents/standards/coding.md`。缺少需求依据时从代码和现有契约核对可验证的行为，注明影响评审的缺口。
3. 阅读实际 diff 和相关完整代码。沿调用链核查上下游、状态变化、错误路径、数据兼容及测试断言。按改动内容检查权限、并发、重试、幂等和部分失败等可触及的风险。用现有测试或明确的代码路径确认问题。
4. 按严重程度给出有证据的发现。每条写明文件与行号、触发条件、行为影响和相关任务或验收编号（如有）。用 P0 标记阻断关键功能或严重数据损失等问题，用 P1 标记重要场景的明确缺陷或回归，用 P2 标记影响较小但可证实的问题。测试缺口需说明哪种行为可能回归且缺乏覆盖。
5. 先列发现，再简述评审范围、执行的验证和未核实的风险。没有可报告问题时直接说明。评审默认只读。用户要求存档时，将结果写入已有工作项目录下的 `review.md`，需要修复时按用户授权处理。
