# 完成与归档

## 核对工作项和完成证据

1. 按用户给出的路径、工单号或当前工作项定位目录，读取适用的 `AGENTS.md`、文档地图、需求、设计、任务、验证和评审记录。明确本次变更的代码范围和证据对应的版本。已有归档时先识别归档位置和同步记录。
2. 核对验收条件、必做任务、项目要求的验证及评审结论。历史工单可用已确认的 PR、工单状态等现有证据。必做事项未完成、必要验证缺失或阻断项未关闭时，保留工作项在原位置，指出缺口和解除条件。用户只要求判断时给出有证据的结论并说明待核实项。

## 判断主规格是否需要更新

沿 `AGENTS.md` 的入口查阅对应的当前规格。主规格使用项目现有的 PRD、业务规则、接口契约或其他长期维护的文档。对照验收条件、实际变更和验证证据，确认行为、契约或长期约束的变化。

| 判断 | 适用情形 | 处理 |
| --- | --- | --- |
| 无需更新 | 变更保持已约定的行为，或现有主规格已覆盖交付后的行为 | 简记依据 |
| 需要更新 | 有证据表明预期行为、公共契约或长期约束有新增、修改或删除 | 写明目标文档、锚点、拟改内容及证据 |
| 待核实 | 规范来源冲突、归属不明或行为缺少验证 | 写明待核实的问题和所需证据 |

用户要求同步或项目现行流程已授权时，重新核对当前主规格，将仍适用且证据明确的变更写入对应文档。保留无关内容，核对更新后的规格和验收证据一致。发现后续交付已替代这次规则时，记录已生效的行为和依据。只要求归档时，记录待同步项及其目标。项目把主规格更新列为必做验收时，按该约定确认完成状态。

## 归档与复核

1. 用户只要求判断或同步时，在所请求的范围完成。归档时优先采用项目明确的完成目录。默认把 `docs/changes/<work-item>/` 移到 `docs/changes/archive/YYYY-MM-DD-<work-item>/`，使用项目约定时区的归档日期。采用 `doc/changes/` 或旧 `increment/` 的工作项沿用各自的文档根和已有归档约定，没有约定时使用对应的 `archive/`。从进行中子目录归档时，使用同一工作项根下的归档目录。
2. 写入 [收尾记录](assets/completion.md)，记录实际验证、主规格判断和同步结果。先确认归档目标和来源均属于本工作项，再核对目标唯一，保留目录内的所有阶段产物，检查移动后会失效的相对链接及受影响的项目入口。发现同名归档时查证它是否已是本工单的产出，避免覆盖其他工单。
3. 移动后复查源路径已移除、目标目录中产物齐全及关键链接仍可用，并回填实际归档路径。再次执行时依据实际目录和记录续办待同步项，已经归档的同一工作项沿用现有位置和日期。发生部分失败时记录实际变更，保留产物并从未完成的操作继续。
4. 汇报归档路径、完成依据、主规格判断，以及已同步或待处理的条目。
