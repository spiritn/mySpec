# 初始化项目文档地图

## 读取项目文档

1. 确认目标项目根目录，读取现有 `AGENTS.md` 和项目已有的文档约定。优先使用用户或项目指定的文档根目录。未指定时检查 `docs/` 和 `doc/`，两者并存时读取两边，记下入口的实际路径。
2. 查找 `backend/`、`prd/`、`rules/`、`fronted/`、`deploy/`、`changes/`。识别现有 `increment/` 作为工作项文档。将现有 `frontend/` 也识别为前端文档，沿用它的实际拼写。沿用项目已使用的其他分类和子目录。
3. 先读文档根目录及分类目录中的 `README.md`、`index.md` 或现有索引。递归核对含文档的子目录，读取适用规则和代表性专题文档的标题、范围与关键段落，根据正文为入口写一句用途。规则、旧方案和已完成迭代若与当前行为或适用范围有分歧，写清需核对的来源。
4. 借用 [子目录参考](references/doc-layout.md) 理解分类。只有用户同时要求初始化文档目录时，才补建需要的目录，沿用现有根目录和命名。两种文档根目录都缺失时，新建布局默认落在 `docs/`。

## 生成或刷新 AGENTS.md

1. 用 [文档地图模板](assets/document-map.md) 将可阅读的文档入口按用途写进项目根目录的 `AGENTS.md`。每行包含阅读时机、实际仓库相对路径和一句内容说明。优先链接分类索引，缺少索引时按主题链接代表性文档。缺少或空的分类在「待补充」中标记。标出无法读取或需要核对的材料。
2. 写明本次需求资料如何定位。优先沿用项目指定的路径和已建立的工作项。新布局使用 `<文档根>/changes/<work-item>/`，已完成的工单归档到 `<文档根>/changes/archive/`。采用 `increment/` 的项目沿用实际路径和归档约定。地图写明进行中和归档入口，开展工作时从进行中入口按工单号查找。
3. 文件不存在时建立 `# 项目开发约定` 标题并写入地图。文件已存在时保留人工内容，只刷新一对完整标记之间的地图。没有标记时追加一个地图区块，复用已有的有效入口。标记异常时保留已有内容，在边界明确时修正地图。当前没有文档根目录时，先记录这一事实和待补项。目录扫描只用来生成导航，源文档的迁移、编辑和归档按用户指定的范围处理。
4. 核对生成的相对链接可读，地图区块唯一，并检查项目原有约束和迭代路径约定。同一份文档在未变化时重复运行应得到同一份地图。报告已读取的根目录、写入位置和待补项。
