# 任务拆解

1. 读取适用的项目指令、工作项的 `design.md` 和 `requirements.md`，沿用既有目录和编号。用户给出足够明确的改动范围和验收条件时，也可直接拆解。
2. 按有独立完成条件的工作拆分，例如实现一个业务路径、落地一次兼容迁移或补齐关键场景验证。每项使用稳定的 `T-01` 等编号，写清预期变化、涉及模块或符号、前置任务、关联验收条件和验证方式。对改动位置已知的任务写明预计新增或修改的路径或符号。位置尚待定位时记录搜索入口和相关设计章节。
3. 按依赖排序，标记因业务决定、环境或外部依赖而阻塞的任务和解除条件。任务彼此无依赖、写入范围与共享契约互不冲突时，可标记在各自前置完成后并行。核对每条验收条件和设计中的必要改动都有对应任务。检查新会话能否凭任务条目和引用的设计定位改动、确认依赖并验证结果。缺少关键契约或验证条件时，标出受影响的任务及解除条件。
4. 用 [任务模板](assets/tasks.md) 新建或更新同一工作项的 `tasks.md`。无既有目录时按项目约定建档，默认使用 `docs/changes/<work-item>/`。更新时保留有效的任务编号、已确认的完成状态及其验证证据。行为要求变化时重新核对受影响的完成状态。
5. 报告任务文件、主要顺序和未决事项。只请求拆解时，以任务清单交付。
